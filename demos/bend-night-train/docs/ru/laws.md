# Законы: что в Bend 2 реально доказуемо

`LAWS.bend` — утверждения, `PROOF.bend` — доказательства, `bend PROOF.bend` —
ворота. Они проходят и печатают `All terms check.` примерно за 0.2 с.

```sh
./tools/bend PROOF.bend
# All terms check.
```

Этот текст — отчёт о том, где проходит граница доказуемого и почему.
Граница оказалась не там, где я ожидал: она проходит не между «сложным» и
«простым», а между **структурой и числами**.

## 1. Что доказано

Утверждения сформулированы на `src/shape.bend` — скелете кадра: та же тайловая
рекурсия, которую выполняет растеризатор, только вместо закрашенного тайла стоит
`Tile{0}`. Лист владеет блоком 8x8 пикселей, а глубина кадра `d` — это глубина
рендерера минус три фиксированных уровня тайла: `Shape.frame.at(d)` срезает их
ровно так же, как `Raster.frame`.

### `consist_slots` — индексная последовательность состава ровно длины k

```python
law consist_slots:
  for k: Nat
  {List.length(&2, Nat, Scene.slots(k)) == k : Nat}
```

Состав строится обходом `Scene.slots(k)` — списка `[k-1, …, 1, 0]`. Геометрия
вагона — это F32 и недоказуема (см. §2), но **ошибка на единицу в числе
вагонов** — проверяемая. Доказательство — индукция по `k`; шаг держится на
том, что `List.length` от cons по определению равен `1n + length(tail)`:

```python
def Laws.consist_slots(k):
  match k:
    case 0n:
      {==}
    case 1n+p:
      %Laws.consist_slots(p) : {1n+List.length(&2, Nat, Scene.slots(p))
        == 1n+_ : Nat}
      {==}
```

Ради этого закона `Scene.consist` пришлось разрезать на
`Scene.slots` (числа) и `Scene.consist.list` (геометрия). Это не косметика:
пока индексы и синусы жили в одной функции, утверждение было невыразимо.

### `quad_pixels` — параллельный сплит на четыре ветви ничего не теряет

```python
law quad_pixels:
  for a: Shape.Frame
  for b: Shape.Frame
  for c: Shape.Frame
  for e: Shape.Frame
  {Shape.pixels(Shape.Quad{a, b, c, e}) ==
     Nat.add(pixels(a), add(pixels(b), add(pixels(c), pixels(e)))) : Nat}
```

Доказывается рефлексивностью (`{==}`) — это буквально определение
`Shape.pixels`. Ценность не в глубине, а в том, что закон сторожит **место
разреза**: `Quad{a,b,c,e}` — это ровно тот узел, который строит параллельный
вызов `a b c e = frame(...) frame(...) frame(...) frame(...)`. Если кто-то
перепутает порядок или потеряет ветку при рефакторинге, закон сломается.

### `frame8` — один тайл на своей глубине это ровно 64 пикселя

```python
law frame8:
  {Shape.pixels(Shape.frame.at(3n)) == 64n : Nat}
```

Глубина 3 — это собственная глубина тайла (`Tile.levels()`), то есть один лист:
8x8 = 64. Проверяется вычислением, и именно он закрепляет сторону тайла и
срезание глубины: изменение любого из них сдвигает счёт.

### `frame_tiles` — кадр глубины 6 это ровно 64 тайла

```python
law frame_tiles:
  {Shape.tiles(Shape.frame.at(6n)) == Nat.pow(4n, 3n) : Nat}
```

`frame.at(6n)` — это 6 - 3 = 3 уровня разбиения на четыре, то есть 4^3 = 64
листа. Именно этот закон ловит потерянное или продублированное поддерево при
сплите.

### `frame_pixels` — кадр глубины 6 это ровно 4096 пикселей

```python
law frame_pixels:
  {Shape.pixels(Shape.frame.at(6n)) ==
     Nat.mul(Nat.pow(2n, 6n), Nat.pow(2n, 6n)) : Nat}
```

64 тайла по 64 пикселя. `quad_pixels` говорит, что стык сходится; этот — что
весь кадр того размера, на который заявлен, так что изменение стороны тайла мимо
не проскочит.

### Ворота действительно закрыты

Проверено отрицательным тестом: `probes/neg/PROOF_bad.bend` — это `frame8` с
утверждением, изменённым на 16.

```
$ ./tools/bend probes/neg/PROOF_bad.bend
Error:
- expected : 64n
- observed : 16n
Location: frame8
```

## 2. Чего доказать нельзя

### F32 непрозрачен

Попробуем самый простой закон про числа с плавающей точкой:

```python
law f32_add_zero:
  for x: F32
  {F32.add(x, 0.0) == x : F32}
```

```
$ ./tools/bend probes/limits/PROOF_f32.bend
Error:
- expected : F32.add(x, 0.0)
- observed : x
Context:
- x : F32
```

Причина видна из `bend base F32`: **все** операции над F32 объявлены как
`law`, а не `def`:

```
law F32.add:
  for a: F32
  for b: F32
  F32
```

У `law` нет тела. Чекер про них ничего не знает и не может упростить ничего,
кроме буквально одинаковых термов. Значит:

- цвет пикселя;
- положение камеры;
- значения `Track.x`/`Track.y`;
- «кадр не зависит от числа потоков»;
- «яркость в границах [0,255]»

— всё это **невыразимо** в текущем Bend 2. Не «сложно доказать», а нельзя
даже сформулировать как закон. Именно поэтому и существует `src/shape.bend`:
законы про кадр сформулированы на его **скелете** — той же рекурсии с тем же
параллельным вызовом, но с константой вместо цвета. Структура — доказуема,
пиксели — нет.

Это подтверждает и официальная демка: `demos/app_ray_tracer_3d/LAWS.bend`
начинается словами «The F32 scene is not claimed» — авторы языка обошли ровно
ту же стену.

### Общий закон 4^d упирается в арифметику, которой в Base нет

Естественное обобщение `frame_tiles` — «кадр глубины `d` содержит ровно 4^d
тайлов». `probes/limits/PROOF_gen.bend` формулирует его в самом маленьком виде,
заменив дерево на его счётчик и сохранив тот же шаг индукции:

```python
def four(+d: Nat) -> Nat:
  match d:
    case 0n:
      1n
    case 1n+p:
      Nat.add(four(p), Nat.add(four(p), Nat.add(four(p), four(p))))

law four_is_pow:
  for d: Nat
  {four(d) == Nat.pow(4n, d) : Nat}
```

Индукция доходит до шага и останавливается:

```
$ ./tools/bend probes/limits/PROOF_gen.bend
Error:
- expected : {Nat.add(four(p), Nat.add(four(p), Nat.add(four(p), four(p)))) == Nat.add(Nat.pow(4n, p), Nat.add(Nat.pow(4n, p), Nat.add(Nat.pow(4n, p), Nat.add(Nat.pow(4n, p), 0n)))) : Nat}
- observed : {four(p) == Nat.pow(4n, p) : Nat}
Context:
- p : Nat
```

Если прочитать обе строки вместе, разрыв виден. `expected` — это цель шага после
раскрытия обеих сторон: `four(1n+p)` превращается в четырёхкратную сумму
`four(p)`, а `pow(4n, 1n+p)` — в четырёхкратную сумму `pow(4n, p)`,
оканчивающуюся на `Nat.add(…, 0n)`. Доказательство предлагает гипотезу про один
`four(p)`, на верхнем уровне; ничто не поднимает её до суммы, потому что нет ни
тактики, ни правила переписывания, чтобы её применить. Шаг на этом встаёт. За
этим стоят два арифметических факта: правая часть цели оканчивается на
`Nat.add(…, 0n)` там, где слева голый `four(p)`, — значит, нужно `x + 0 = x`;
а суммы вложены по-разному — значит, нужна ассоциативность. Ни того, ни другого
Base не даёт: `bend base Nat` показывает определения `add`, `mul`, `pow`,
`double` и **ни одной леммы** об их алгебре.

Официальный ответ на это — демка `demos/proof_numerics`: там заново определяют
`add`/`mul` и доказывают `add_comm`, `add_assoc`, `mul_comm`, `mul_dist`. Иначе
никак: у Bend нет тактик, нет поиска переписываний, каждый шаг ассоциативности
пишется руками.

Практический вывод для law-driven development: **любая программа, где есть
арифметика, сначала платит за библиотеку арифметики**. Для нашего рендера это
означало бы: доказать `x+0=x`, доказать ассоциативность, затем обобщить
`frame_tiles` до `4^d`. Пять законов, которые есть сейчас, этого платежа не
требуют — они держатся на структуре списка и дерева и решаются вычислением.

## 3. Что это значит

![Граница: слева структура доказуема, справа числа — нет, потому что каждая операция над F32 объявлена законом без тела](../../assets/readme/laws-boundary.svg)

| | доказуемо | недоказуемо |
|---|---|---|
| форма кадра, число тайлов и пикселей | да | |
| полнота параллельного сплита | да | |
| число вагонов | да | |
| цвета, освещение, туман | | F32 непрозрачен |
| положение камеры и путь | | F32 непрозрачен |
| `4^d` в общем виде | | нет алгебры Nat в Base |
| детерминизм между потоками | | следствие из F32 |

Последняя строка — отдельная ирония. Детерминизм рендера **измерен** — в
`bench/results.csv` лежат 54 прогона по глубинам 8, 9 и 10 и числам потоков от 1
до 32, и дайджест кадра — одно значение на глубину, — но **не доказан**: чтобы
его сформулировать, нужны уравнения на F32-значениях, а их у чекера нет.

Получается честная картина для этого проекта: ворота законов ловят ошибки
**структуры** — потерянную ветку квадродерева, лишний или недостающий вагон,
сломанную рекурсию, — и не ловят ошибки в **числах**. Это гораздо больше, чем
ничего, но заметно меньше, чем обещает слово «proof» на обложке.
