# Как это запускать

```sh
make proof                  # ворота законов: должно быть "All terms check."
make build                  # нативный бинарник через clang
make frame                  # кадр 512x512 в out/frame.png
make bench                  # прогон в bench/results.csv
make compare                # рендер + эталон + метрики, 1024x1024
make video                  # записать клип: mp4, постер, gif

./tools/live.sh             # смотреть, как он рендерит
./tools/bend src/main.bend  # проверка и запуск на JS-бэкенде
```

Бинарник принимает `--threads N`; сцену рендерер читает из окружения:

| | |
|---|---|
| `NT_DEPTH` | глубина квадродерева; кадр `2^d × 2^d` |
| `NT_S` | положение вдоль пути, метры |
| `NT_T` | часы анимации, секунды (частицы, свет в окнах) |
| `NT_MOTION` | `1` — качка и покачивание поездки, `0` — заморожено |
| `NT_YAW`, `NT_PITCH` | пришпилить голову; без них решает auto-look демки |
| `NT_HEAD` | `1` — голова высунута в окно |
| `NT_PPM` | `1` — писать `out/frame.ppm`, `0` — только посчитать |
| `NT_VIEW` | `1` — поток кадров в stdout вместо одного файла |
| `NT_FRAMES`, `NT_MS`, `NT_STEP` | кадров, время первого, шаг между ними |

```sh
NT_DEPTH=10 NT_S=150 NT_MOTION=0 NT_PPM=0 ./out/night-train --threads 16
```

## Смотреть, как он рендерит

Рендерер безголовый и пишет текстовый PPM, поэтому на экран его выводит
`tools/live.sh`: по процессу на кадр, кадры уходят в stdout и дальше в `ffplay`.
На 24 потоках это **5.6 fps при 256x256** и **4.4 fps при 512x512** — достаточно
медленно, чтобы разглядеть, и достаточно быстро, чтобы следить. `NT_VIEW=1` вместе с
`NT_FRAMES`, `NT_MS` и `NT_STEP` гонят тот же поток руками; `tools/clip.sh` снимает
клип оффлайн, где рендерер не привязан к стенным часам.

## Сравнение с оригиналом

`tools/render_reference.py` рендерит оригинальную демку безголово на закреплённой
камере и с засеянным PRNG, поэтому кадр воспроизводим; `tools/compare.py` кладёт кадр
Bend и кадр эталона рядом и печатает метрики ошибки, а `make compare` запускает и то,
и другое. `tools/compare_video.sh` делает то же вдоль поездки и пишет клип, постер и
GIF, который встроен в README. Страница на кадр — намеренно: частицы и дым демки
несут состояние между кадрами, поэтому кадры одной браузерной сессии не были бы теми
стоп-кадрами, за которые себя выдают.

## Обёртка `tools/bend`

В этом окружении `$HOME` доступен только для чтения, и голый `bend` не может писать
в `~/.bend`, поэтому всё идёт через обёртку. Обёртка ещё и **запрещает `--publish`**:
хаб Bend — контентно-адресуемое хранилище без аккаунтов и без удаления, поэтому
опубликованный пакет остаётся публичным навсегда. Снять запрет может только человек,
выставив `BEND_ALLOW_PUBLISH=1`.
